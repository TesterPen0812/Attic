# Attic iPhone · Stage 5a fake-transport sync core

Status: isolated implementation and test source for `iphone/build-fakesync`, branched from `912cbb46` on 2 November 2026. **Not activated in any Local configuration.** Stage 5b, real CloudKit, container setup, entitlements, signing and account/data migration are explicitly excluded.

## Boundary and integration

All added Swift lives under `#if ATTIC_CLOUD_SYNC && !ATTIC_LOCAL_ONLY`. `PhoneFakeSyncSession` owns the deterministic application state machine. `PhoneFakeSyncTransport` defines the send/ack/fetch contract. `PhoneFakeSyncServer` simulates private database event delivery, deduplicates operation identities, partitions by account/environment, and injects lost receipts, incomplete assets, duplicates and reordering. `PhoneFakeSyncCKSyncEngineBoundary` can accept an *injected* `CKSyncEngine` and delegate-parsed events when Stage 5b is authorized; Stage 5a never initializes it, calls an SDK method, registers notifications, or accesses a container.

`PhoneFakeSyncRepository.transaction` is an atomic, serializable **test double**, not an existing SwiftData writer hook. A real adapter must register **every** writer (`TaskStore`, note/document transactions, links, tag colours, Draw, archives, restores and library commands) in the *same SwiftData transaction* that saves the local change. It must store outgoing mutations, state serialization and CKRecord system fields in account/environment-specific persistence. It must use fresh `ModelContext`s for imports, commit the imported rows before persisting the import checkpoint, and refresh presentation contexts after commit. Neither the Mac Local store nor the existing iOS Local store has been modified by this branch. The new files need generator/source membership in a future explicit sync target: Local builds use `ATTIC_LOCAL_ONLY` and compile out both the implementation and these tests.

## Wire invariants

| Item | Behavior exercised by the fake core |
| --- | --- |
| Typed identities | `task/<uuid>`, `taskNoteLink/<note-uuid>`, `noteHead/<uuid>`, `noteRevision/<note-uuid>/<revision-uuid>`, `assetManifest/<uuid>`, `assetBytes/<uuid>`, `taskPlacement/<uuid>`. Physical duplicate task rows share one logical task record name. |
| Outgoing changes | Every local mutation and outgoing intent commits together. Each queued operation has an immutable identity and generation; acknowledgments match **both** plus the record name. Dependencies remain blocked until earlier operations are acknowledged. |
| Note history | Immutable SHA-256-checked bytes, format, parent revision IDs and attachment manifest IDs are retained. The mutable head may advance only after the required asset bytes and immutable revision have been acknowledged. Ancestry picks a descendant; unrelated offline branches remain side by side for review until a revision referencing both is published. |
| Imports | Buffer out-of-order server sequences, replay identical events idempotently, reject corrupted payloads, and advance contiguous checkpoint and imported state atomically. Imports never enqueue another outbound change. A completed fetch counts only when no sequence gap remains. |
| Deletion | Explicit tombstones on tasks and note heads suppress stale additions; historical versions survive. A restore explicitly cites a known tombstone operation. Deleting a task does not imply deleting its note. No finite tombstone pruning is attempted. |
| Assets | Metadata and immutable bytes travel independently. Bytes are checked against manifest count and SHA-256 before becoming available. Missing bytes are **waiting**, never proof of deletion; interrupted sends and incomplete delivery retry. |
| Account isolation | Environment and account scope partition ledger, queue, system fields, engine-state blob and fetch token. Fetch events and send acknowledgments carry their originating scope so delayed callbacks cannot import into a different account. Switching accounts preserves the previous account's pending work; sign-out blocks sends. Completing a fetch is a session-local gate, reset after restart and account changes. |
| UUID duplicates | Physical task copies are retained as separate rows. Consistent copies all receive a remote import. Divergent copies veto exporting edits and cleanup; no unique constraint, random winner, or repair-on-read is introduced. |
| Task-note ownership | Two independently created note links for the same task are retained as multiple candidates for review. The link records have distinct stable note UUID identities plus immutable operation IDs, so an unrelated offline candidate cannot overwrite another; neither note is deleted or replaced. |
| Done cleanup | Before each cleanup decision, fetch and commit all pending remote changes. Use the device's own calendar day boundary, compare completion instants, and archive only whole eligible families. Divergence, missing relatives, open members and concurrent forks veto the related family. The archive is a task version with `doneLoggedAt` plus an active-placement tombstone, preserving history. |

This is an application-level conflict and transport **model**, not a verified CloudKit schema. Asset quotas, large-document streaming, change-tag retries, record zone resets, token expiry, replay after the server's retention window, account identity hashing, secure persisted storage, production tombstone retention, and transactional SwiftData mapping still require Stage 5b integration and independent device proof. `PhoneFakeSyncCKSyncEngineBoundary` receives *already decoded* events; a CKRecord codec and actual `CKSyncEngineDelegate` lifecycle are not part of Stage 5a. In particular, no claim of successful network synchronization is made.

## Tests and constraints

The new `PhoneFakeSyncEngineTests.swift` exercises crash/commit rollback and replay after a lost receipt; duplicate and out-of-order imports; checkpoint rollback; stale acknowledgments; two offline note forks and deliberate resolution; two offline task-note ownership candidates; tombstones, old offline edits and restore; interrupted/missing/corrupted assets; account + Development/Production boundaries; duplicate UUID rows and divergence preservation; and cross-device reopen/Done-family maintenance including a timezone transition. It constructs **only synthetic fixtures** and fake stores.

The Stage 5a test target must be built with `ATTIC_CLOUD_SYNC` **without** `ATTIC_LOCAL_ONLY` (never both), with the new core and test files added to a dedicated sync-only target/configuration by the lead. Do not run Xcode on the MacBook Pro. Builds and tests belong to the MacBook Air, coordinated through `ssh air` and `Scripts/xcodebuild_locked.sh` once the lead has an exclusive Air slot. Because the owner of `iphone/build` controls the project generator and staged Stage 3 files, this branch intentionally does not change `Scripts/generate_project.rb`, `project.pbxproj` or existing app code; its tests are **not** discovered by the current Local scheme. Verification must record exact command, host and results rather than describing source-only checks as passing tests.
